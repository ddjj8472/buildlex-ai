# 실제 민원(법제처 법령해석례 60건) 평가

- 평가셋: `tests/minwon.json` — 건축법 관련 법제처 해석례 60건(질의요지·회답·이유·관계법령).
- 실행: `/api/ask`에 질의요지를 그대로 넣고, `holdout`으로 같은 해석례를 근거에서 제외(정답 유출 방지). 프리뷰 배포에서는 `GET /api/eval-minwon?i=N`(운영에서는 404)으로 브라우저 없이 한 건씩 실행할 수 있다.
- 채점: 결론이 법제처 회답과 일치하면 C, 반대면 W, 판단 유보·일부만 맞음 H, 생성 실패 F. 회답 이후 법령 개정으로 현행법과 달라진 4건은 X로 제외 → **56건 기준**(모든 실행에 같은 기준 적용). `grades.json`에 건별 기록.
  - 3번: 건축법 제60조④(2022 신설), 31번: 제61조② 개정
  - 4·15번: 국토계획법 제78조⑦(2021.10.8 신설)로 용적률 완화 규정의 중첩 적용이 허용됨(회답은 2021.4~5)
  - 8번 나: 시행령 제86조②1(2015~2017 개정)이 보행자 전용도로를 명시 → 현행법 기준으로 채점(가는 회답 그대로)

## run4에서 바꾼 것 — 국내외 사례·논문에서 가져온 방법

1. **법리 분석 단계**(`lib/reason.ts`, 검색과 답변 사이): 법적 삼단논법으로 쟁점 → 대전제(조문 원문 인용) → 요건 분해(충족/불충족) → 단서·예외·준용 → 해석 방법 → 결론을 JSON으로 만든다.
   - Legal Syllogism Prompting(Jiang & Yang, 2023), SyLeR(arXiv 2504.04042): 대전제·소전제·결론 구조
   - Chain-of-Verification(Dhuliawala et al., ACL Findings 2024), lexdiff·korean-law-mcp(원문 대조형 RAG): 요건·단서마다 인용문을 검색 원문과 대조(`ground`)하고, 원문에 없는 조건은 버리고 "제외한 조건"으로 표시
2. **독립 분석 3개 + 판정**: 기본 모델·빠른 모델·기본 모델(온도 0.7)이 병렬로 분석(Self-Consistency, Wang et al., arXiv 2203.11171). 결론이 일치하면 답변이 그 결론을 따르고, 엇갈리면 다수결을 강제하지 않고 양쪽 결론과 근거를 답변 모델에 넘겨 원문으로 판정(Universal Self-Consistency, Chen et al., arXiv 2311.17311). 이때 문언이 결론을 직접 말하는 쪽을 우선.
   - 가벼운 모델 3개의 다수결이 해석 원칙을 지킨 답변 모델을 뒤집는 사례가 있어 이렇게 바꿈.
3. **해석 원칙 한 곳으로**(`lib/canons.ts`): 법제처 법령해석 방법(문리→체계→목적론, 특례 엄격해석, 특례 중첩은 명문 규정 필요, 특별규정 우선, 준용은 바꿔 읽기, 단서는 가리키는 조문만, 다른 법률 허가는 의제 규정 없으면 면제 아님, 용어는 근거 조문 범위로, 부칙·경과조치는 문언대로)을 분석·답변 프롬프트가 함께 씀.
   - 원칙이 답변 프롬프트에만 있고 분석 프롬프트에 없어서, 답변이 분석 결론을 따르다 기존에 맞던 사례가 틀어진 문제가 있었음.
4. **응답 형식 견고화**: 모델이 `[{"issues":[…]}]`처럼 배열로 감싸 답하면 분석이 버려지던 문제 수정(투표 수가 1~2개로 줄던 원인).
5. **지연 관리**: 분석은 22초 예산. 느린 flash 별칭은 이 안에 끝나지 않아 기본 투표자에서 뺌(`GEMINI_REASON_MODELS`로 변경 가능). 판단형 질문만 이 단계를 거치며 응답이 약 8~15초 늘어남.

CLAUSE 벤치마크(arXiv 2511.00340)가 지적한 것처럼 LLM은 미세한 법적 오류를 놓치기 쉬워, "결론을 원문 문장에 묶는" 쪽으로 설계함.
